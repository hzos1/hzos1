# 設計筆記

這是課程示範的對照表，不是可繳交的報告正文。日期：2026-11-17。

## 頁面

同一個網頁。手機用底部選單，電腦用側欄。登入後主畫面是今日概覽。聊天室是選單上的獨立頁，不是預設入口。

| 路由 | 可見的事 |
| --- | --- |
| `/onboarding` | 身高、體重、年齡、生理性別、活動量、目標體重、cut／bulk／maintain、每週訓練天數。未填不進入其他頁。 |
| `/home` | 預設主畫面。`estimate_needs` 的 BMR、PAL、TDEE、課堂目標。最近五筆已查資料庫的餐。檔案約 30 天未更新時顯示一次性提醒，可關掉；關掉後要等下次更新再過約 30 天才再出現。不是醫療追蹤。 |
| `/analyze` | 拍照、相簿、安全連線上的即時鏡頭。認菜工具只出菜名。使用者確認菜名和克數後才 `lookup_meal`。 |
| `/plan` | `suggest_meal` 按檔案組早餐、午餐、晚餐（預算夠再加小食），每項有克數、熱量、營養素、來源、理由、處理和替換。`check_constraints` 與 `training_guidance` 仍由工具產生。不是模型開的治療餐單。 |
| `/chat` | 選單上的獨立頁，不是登入後的主畫面。提示按鈕把課程式句子填入輸入框，「改好這句提示」只在瀏覽器改寫草稿，不另外呼叫模型。氣泡標出哪個 agent，可展開 ReAct。 |
| `/more` | 只連到檔案頁。 |
| `/profile` | 查看和修改同一份檔案。 |

## 課程技巧對照

- **迴圈。** 每一輪是目標、規劃、工具、觀察、更新狀態。停止條件寫在軌跡的世界狀態：有沒有餐、剩餘熱量、餐單有沒有通過檢查。成功不是一句飲食建議。
- **三個組件。** Planning 在 `src/planning.js`。Tools 在 `src/tools.js` 與 `src/harness.js`。Memory 在伺服器。身體檔案存在本機使用者檔（`var/`，已 gitignore），密碼只存 scrypt 雜湊。登入用 httpOnly cookie。聊天室在有 `XAI_API_KEY` 時由 Grok 選工具；沒有金鑰就用本地模型，再不行就用確定性規劃。
- **ReAct。** 各功能頁和聊天室都可展開 thought、action、observation。
- **工具契約。** `GET /api/meta` 列出 JSON schema、允許的網路和可寫欄位。模型只可選工具；熱量由資料庫工具寫入。
- **Harness。** 未知工具、不在使用者句子裡的菜名或克數、模型自填的卡路里欄位都會被擋下。上限 8 次工具、8 圈。失敗時改走確定性規劃，軌跡標 `deterministic-recovery`。
- **檢索。** 營養數字來自已引用的 USDA SR Legacy 與臺灣食藥署列，或有金鑰時的 USDA 即時查詢。這是工具檢索，不是向量 RAG。沒有做 SFT、RL、PEFT、DPO、PPO、GRPO 或 Generative Agents。
- **人在迴圈裡。** 相片後必須確認菜名和克數。未確認前不查熱量。
- **安全。** 頁首免責：不是診斷、臨床營養或私人教練，不會代下單。OWASP 對照：不讓模型提供未引用的數字（LLM09）；工具不能下單或開治療（LLM06）；金鑰只在環境變數（LLM02）；有呼叫上限（LLM10）；工具輸出先驗證再顯示（LLM05）；使用者句子當資料，不當指示（LLM01）。

## 計算規則

Mifflin–St Jeor × FAO/WHO/UNU PAL：少動 1.50、中度 1.75、高活動 2.10。維持等於 TDEE。減脂是 TDEE 減 500 kcal。增肌是 TDEE 加 400 kcal。500 kcal 的公開來源是 NIH News in Health（2022-12）約每週 1 磅，不寫成正好 0.5 公斤。目標低於 BMR 的計劃會被拒絕。差距超過 10 公斤只警告，不加大赤字。公式只有男、女兩條算式。增肌不量度肌肉公斤。
