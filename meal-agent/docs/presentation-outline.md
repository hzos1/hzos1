# 報告大綱

10 分鐘以內的條列，不是講稿，也不是報告正文。三個人都可以被問到自己那一段。

## 1. 問題（約 1.5–2 分鐘）

- 使用者要的是今天還剩多少熱量、下一餐能不能過檢查、附近有沒有地圖上的店，不是一段飲食文案。
- 所以預設頁是 `/home`，不是聊天室。聊天室在 `/chat`，由「更多」進入。
- 每個功能是獨立路由，底部選單切換；電腦和手機用同一個網頁。

## 2. 迴圈和工具（約 2.5 分鐘）

- 迴圈：目標 → 規劃 → 工具 → 觀察 → 更新狀態。畫面可展開 thought / action / observation。
- Planning、Tools、Memory 分開。身體檔案先在入門頁提交，之後的工具只讀這份檔案。
- 工具有 JSON schema。模型可以選工具，不能自己填卡路里。Harness 擋下越權欄位、不在使用者句子裡的克數，以及超過 8 次的呼叫。
- 營養數字是資料庫列，不是向量 RAG。沒有做 SFT、RL 或 Generative Agents。
- 可引用：Weng 2023 agents；Weng 2026 harness；OpenAI harness engineering 2026；Yao 等 ReAct，ICLR 2023。

## 3. 示範（約 2.5 分鐘）

- 註冊頁填電郵、密碼、身高、體重、年齡、生理性別、活動量、目標體重、目標類型、訓練天數，並確認免責。
- 今日概覽顯示 Mifflin–St Jeor × PAL 的工具結果。
- 分析頁：相簿或 HTTPS 鏡頭。先確認菜名和克數，再出現來源編號和營養素。
- 計劃頁：餐單、衞生防護中心原則、訓練天數對照。餐廳頁：沒有同意就不查；查到的店沒有菜單熱量。
- 最後才打開聊天室，展示另一個 agent 氣泡和同一套軌跡。

## 4. 數字和安全（約 2 分鐘）

- `npm run eval` 在 2026-11-17 的輸出：29 個菜名檢查，名稱對上 28/29（0.9655）。這是別名對到引用列，不是相片實驗，也不是臨床研究。
- 沒對上的是英文 `banana`：USDA `173944` 和臺灣列的英文名都精確對上，工具回覆 ambiguous，所以沒有給卡路里。
- 有標註而且成功解析的列，熱量 MAE 和 MAPE 都是 0。缺列的蛋撻、腸粉、菠蘿包、絲襪奶茶、雲吞麵不計入 MAE。
- 三個預算 180、450、700 kcal 的建議都沒有超出。只記錄一餐白飯不會自動產生超標餐單。
- 頁首免責。不代下單、不開治療餐單、不編成私人課表。金鑰不進倉庫。店名當資料，不當指示。

## 5. 來源和分工（約 1 分鐘）

- 營養列：USDA SR Legacy 與臺灣食藥署開放資料，見 `docs/meal-ai-sources.md`。
- 熱量公式、500 kcal、WHO 飲食和活動、衞生防護中心份量、OpenStreetMap，出處寫在同一份筆記和工具回覆。
- 三人可分別講：頁面和檔案、工具與 harness、安全與這次 eval。
